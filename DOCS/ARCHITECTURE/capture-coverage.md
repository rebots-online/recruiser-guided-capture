# Capture coverage on the native viewfinder

Status: executable architecture proposal for the current swarm; no coverage implementation is claimed by this document. Root integrates its packets into CHECKLIST before dispatch. Authority: Robin requested direct shading of already captured and weak areas, useful overlap between passes, large intuitive cues, and the actual Stitch design connected to native capture. Scope is lightweight capture guidance; reconstruction remains a later on-device operation.

## Evidence and the contract amendment

CodeGraph reports an up-to-date graph with 138 files, 2,306 nodes and 8,656 edges. Targeted exploration confirms the existing native ARCore owner, OES camera renderer, journal writer, observation recorder and platform-free guidance/fusion. CHECKLIST is the current capture contract. This new Markdown target does not already exist; no product source was changed for this proposal.

Existing CameraBackground draws the camera image. SessionObservationRecorder copies camera/depth observations, persists their assets, appends frame records and runs asynchronous quality analysis. CapturePackageWriter.append flushes a text writer but only periodically fsyncs journal files. Therefore neither an acquired ARCore frame nor a returned append call alone proves durable saved evidence. The coverage boundary must receive a successful fsync acknowledgement.

The existing Pause closes the ARCore Session and every resumed recording receives a new worldFrameId. That cannot support registered overlap across a stopped pass. Required amendment: **Stop pass/Pause while the native viewfinder remains visibly open stops recording and retains the live ARCore Session for tracking. Start next pass may reuse the same worldFrameId only while that same Session has tracked continuously.** The UI says `Paused · view only`; no new observation receives saved-coverage credit. Finish, leaving the viewfinder, backgrounding, permission/camera loss or process interruption still releases the camera and invalidates registration. This amendment never resumes recording automatically.

If tracking becomes PAUSED/STOPPED, immediately hide all spatial coverage. Treat registration as invalid even if the same Session later reports TRACKING; clear the map, retain old source data, close the old pass and assign a new worldFrameId before accepting new saved coverage. No current component supplies a validated relocalization transform, so no automatic old-map restoration is allowed. A selected vignette or human-readable tag never acts as a geometric registration identity.

## Visible meaning

| Native overlay | Meaning grounded in saved observations | Rendering |
| --- | --- | --- |
| Green | At least two useful, distinct retained views of this observed patch | Translucent green footprint with solid outline and sparse dot pattern |
| Blue | The patch is retained, but overlap is weak or image quality is unresolved | Translucent blue footprint with broken outline / diagonal hatch |
| Red | This spatially trusted patch has retained image evidence known unusable and no useful retained view | Translucent red footprint with crossed hatch and outline |
| Unshaded | No trustworthy spatial evidence, an occlusion, unavailable depth, or unknown registration | Leave the camera image unchanged |

Green means `Saved overlap`, never `Complete`. Blue means `More overlap`. Red means `Retake this area`, never `Unseen/failed`. A later bad frame cannot turn a patch with two retained useful views red. New/unknown space is not a negative result. There is no room-completion percentage, inferred room boundary, LiDAR claim, hidden-geometry fill or Gaussian-splat-quality claim.

The shading is the primary feedback. Large secondary cue words are limited to `Steady`, `More overlap`, `Retake`, `Tracking lost`, `Paused` and `Saving`. Include a visible three-colour/pattern legend with these short meanings; do not depend on tiny text or colour alone. Exact layout, buttons, typography and final colour tokens come from the frozen Stitch artifact matched to recruiser.html. Native GL implements the actual spatial shading; a screenshot, web canvas or text-only status is not acceptance.

## Observation-to-overlay flow

1. Existing ARCore owner acquires and promptly closes images. Retention continues at its existing sampled rate. At most two samples per second are nominated for coverage; nomination never delays media recording or creates coverage credit.
2. The retention worker writes original JPEG/depth/confidence assets using the existing atomic/fdatasync path. A nominated frame uses `appendCommittedFrame` instead of append; it receives one receipt only after the frame line and its existing asset references are durable. Non-nominated frames use the existing append path and remain fully retained.
3. Recorder passes a bounded CoverageEvidence and matching FrameCommitReceipt to the coordinator after persistence. If image association, calibrated depth or tracked pose is unavailable, retain the observations and issue appropriate 2D quality cues but no spatial patch. Never synthesize an identity pose or use a depth visualization as geometry.
4. Coordinator replaces stale pending analysis with the latest nominated frame; it does not drop original observations. The accumulator accepts only receipts matching session, frame ID, world ID and timestamp. A rejected/failed commit contributes nothing, even if it appeared in the live preview.
5. Quality may arrive before or after the receipt. Until matching persisted quality is known, retained geometry is blue. Update only the referenced retained frame evidence; a report for an unretained/different-world frame does nothing. The quality report itself must be appended and fsynced before it can cause a green/red classification; its native callback therefore follows writer.flush on the coverage sample path.
6. Renderer consumes an immutable latest snapshot, uses the current ARCore camera view/projection after setDisplayGeometry, and draws over CameraBackground on the same GL thread. It does not query the journal, allocate bitmaps or run reconstruction in draw().
7. Stop pass freezes accumulation, saves a derived report and keeps live tracking/viewfinder feedback only while that visible camera Session remains valid. Start next pass can show same-world retained coverage immediately. Finish/background invalidates generation, clears the renderer and releases camera resources; new captures begin unshaded.

## Conservative patch and overlap algorithm

Use texture-camera intrinsics scaled to raw-depth dimensions, independently of CPU JPEG calibration, as in the [ARCore Raw Depth codelab](https://codelabs.developers.google.com/codelabs/arcore-rawdepthapi). Different CPU/depth crops must not be treated as the same intrinsics; see the [Depth coordinate conversion guide](https://developers.google.com/ar/develop/java/depth/developer-guide#converting_coordinates_between_camera_images_and_depth_images). Keep +X right/+Y up/-Z forward and camera-to-world pose conventions from CHECKLIST.

For each nominated retained frame, uniformly sample at most 4,096 depth pixels using a deterministic grid stride. Require tracked finite pose, valid texture calibration, retained associated image timestamp within 2ms, raw-depth timestamp within the existing 100ms bound, depth 100..10,000mm and confidence at least 128. Zero/low-confidence/stale depth creates no patch. Reject pixels whose valid local neighbours show a depth discontinuity larger than max(0.10m, 0.05×depth); missing neighbours produce isolated small footprints, not inferred continuous surfaces. This avoids drawing a back wall across a foreground edge.

Unproject to camera XYZ with existing CpuDepthUnprojector conventions and transform into the recorded world frame. Quantize by floor(XYZ/0.10m). One frame contributes at most once per patch, irrespective of pixel density. Retain the first accepted spatial position in a cell so later samples cannot move a coloured zone onto unseen space. Footprint radius is min(0.04m, half the sampled depth-pixel spacing at that range); bound its rendered diameter to 4..40 pixels. Do not join patches into surfaces, dilate across holes or colour a convex hull.

Maintain at most two representative useful-view camera positions/directions and frame IDs plus two rejected evidence IDs per patch. A useful retained view has confidence at least 192, valid image association, and none of image-unavailable, low-texture, image-soft, underexposed, overexposed or tracking-lost in its persisted QualityReport. These are provisional quality thresholds inherited from N2, not tested guarantees of 3D accuracy.

A second view counts as distinct only when its camera centre is at least 0.08m from the first **and** the angle between camera-to-patch rays is at least 5 degrees. Time alone, turning in place, repeated identical bytes or another frame ID cannot create overlap credit. A view over 75 degrees from a reliable locally estimated surface normal is blue/weak; when a normal cannot be estimated from agreeing neighbours, do not claim incidence quality and keep the patch blue. Normals are local sample estimates, not a mesh or surface truth.

GREEN requires two useful distinct views and reliable normal/association evidence. BLUE covers one useful retained view, unknown/low-texture quality, insufficient baseline, weak confidence, uncertain normal or overlap. RED requires trusted geometry/confidence/pose and at least one localized persisted image-soft/underexposed/overexposed finding, with no useful retained view. Green/blue evidence takes precedence over a later failed image of the same patch. Unseen cells are absent. A three-pass sequence can improve existing evidence; it cannot fill space that was not observed.

## Native rendering and occlusion

Upload packed XYZ/radius and state buffers only when a snapshot changes, at most 2Hz. Draw GL_POINTS footprints using current ARCore view/projection matrices; shader gl_PointCoord supplies green dots, blue diagonal hatch and red cross-hatch, with a stronger outline and translucent centre. Preserve recognizable camera detail. Use premultiplied alpha consistently and restore GL depth/blend/program bindings after drawing so the existing background and later native rendering remain correct.

Acquire current raw depth/confidence for occlusion at most 10Hz on the existing camera/GL owner; close both Images before any second acquisition by the retention sampler. This is an acquired visibility mask, not saved evidence or a source of new coloured patches. Upload packed depth16 and confidence8 into bounded GLES2 textures. Derive NDC→TEXTURE_NORMALIZED UVs with frame.transformCoordinates2d so fold, crop and orientation are handled by ARCore rather than guessed screen ratios.

The fragment/CPU-reference visibility predicate requires confidence >=128, depth 100..10,000mm, mask age <=100ms in a comparable camera clock, and abs(patch camera-plane depth − live depth) <=max(0.08m,0.03×liveDepth). Unknown/invalid/old occlusion depth suppresses that footprint. Behind-camera, off-viewport and mismatched-generation patches are suppressed before shading. Foreground occluders therefore do not inherit a saved wall's colour. If raw depth is too sparse or unavailable, the surface overlay becomes sparse or disappears honestly; image quality cues continue. No inferred dense mask is substituted.

Before a draw, require snapshot.worldFrameId and generation to match the active controller plus current TRACKING state. A tracking-loss event clears GL buffers immediately, before a pending worker result can publish. A late result from a closed generation is rejected. On valid same-world Pause, retained shading follows the still-live viewfinder, but the cue says Paused and no acquired view changes patch evidence. On tracking recovery without proven registration, start unshaded in a new generation/world rather than jumping old shading onto the camera image.

## Depth-unavailable and cross-pass fallback

When no usable calibrated depth exists, show live image-space warnings and a clearly separate thumbnail of the last durably saved useful frame, labelled `Last saved view`. It can help the person visually overlap a new pass, but it is not registered and must not be stretched over the live camera image or turned into a coloured spatial zone. Do not derive room geometry from gyroscope, accelerometer or GPS alone.

After Finish/background/new Session/tracking ambiguity, the last-frame thumbnail may remain only as that 2D reference. Display `New scan frame` once and clear old coloured footprints. Session/vignette names continue grouping source data, while spatial maps remain separate. Future relocalization may only restore an old overlay through an explicit measured transform with its own acceptance contract; this implementation has no such path.

## Bounded operation and durability

At most 20,000 spatial patches, 4,096 sampled pixels per nominated frame and 2 nominated frames/second. Keep one pending observation and one immutable published snapshot; dropping derived work increases droppedAnalysisFrames and never deletes media/sidecars. Reject duplicates/out-of-order frame timestamps within an epoch and bound the recent quality association cache to 8 nominated frames. Evidence with late quality beyond the cache remains blue; replay can recompute it later.

Use packed arrays for spatial positions, normals, reference views and states, with a bounded voxel-key index and bounded frame-ID dictionary. Reject inputs over existing depth/image bounds before allocating. Target <=32MiB additional live coverage heap; it is a design cap enforced by fixed allocation sizes, not a measured Fold5 footprint. Render at most 8,192 nearest visible patches from a snapshot; omitted patches remain saved in the derived report and cannot be described as unseen or complete. At capacity, update existing patches, admit no new cells and show `Coverage limit` beside the normal capture control; retain all original observations.

Coverage CPU work runs outside the camera/GL/UI threads. The GL thread only performs bounded depth copying/texture upload, matrix setup and one footprint draw. Disable new analysis under severe thermal status before capture is sacrificed. Because visibility still requires fresh live evidence, suppress old shading when the mask cannot keep up. Record analysis-limit/thermal-suspension events; there is no promise of a frame rate or phone-specific temperature bound until measured.

On stop/finish, save the derived coverage report atomically only after the relevant frame/quality journals are durable. Export includes it as an ordinary declared, hashed derived asset under existing package v1; no extra required stream, schema reinterpretation or reconstruction reference is introduced. A corrupted/missing derived report is recomputable from originals and never invalidates their retained state. Playback may rebuild coverage from persisted records without opening a camera, using its own replay generation and recorded timestamps.
