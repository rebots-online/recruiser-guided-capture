# Design System: Recruiser capture

Authority: Robin's existing recruiser.html visual reference and explicit capture UX instructions. Stitch design-taste supplies the document structure; reference fidelity, accessibility, truthful state and low-distraction native capture override its generic font, asymmetric-hero and perpetual-animation preferences.

## 1. Visual theme and atmosphere

Camera-first, compact spatial editor. Graphite panels, a restrained seafoam accent, outlined cube and lowercase recruiser identity. Density 5, variance 2, motion 2. This is an instrument for retaining memories, not a marketing landing page. Most of the capture screen belongs to the real camera. Guidance feels like panoramic photography but adapts to the person's movement instead of demanding a route.

## 2. Colour palette and roles

- Graphite canvas #0c1117; panels #111922; secondary #1b2833.
- Main text #e4eef2; muted text #92a6b5; borders #273744.
- Seafoam action #75e0ce with dark action text #06221e.
- Destructive action #ff9387, confined to confirmed removal controls.
- Semantic native overlays: green saved overlap, blue weak retained evidence, red localized unusable retained imagery. These are evidence states, not extra brand accents. Unknown areas remain unshaded. Hollow blue aiming targets are visually distinct from filled blue evidence.

## 3. Typography

Arial, Helvetica, sans-serif faithfully matches the supplied viewer. ui-monospace for optional measurements. Body 16px, headings controlled 20–28px, button labels at least 16px. No running textual capture instructions; Details contains explanations. Do not replace the reference with generic premium-font styling.

## 4. Components

Actual Stitch-exported library, viewfinder, review, processing and revisit markup/CSS/SVG are the source components. Integrate by cleaning unsupported claims/demo behavior and binding real state, not substituting a fresh hand-drawn UI. Controls have minimum 48px targets and 6.4px corners, seafoam primary fill, restrained borders, visible focus and pressed states.

Library starts empty after the real storage read. Session names, tags, dates, counts and thumbnails come only from saved data. Vignettes group captures without merging spatial coordinate frames. Selected deletion is explicitly confirmed and recoverable. Processing has no numeric percentage without a measured denominator; progress follows the real job and success follows its completed write. Technical readings are optional Details, never fabricated decoration.

## 5. Layout

Mobile first at 390px; support narrower folded phone widths without horizontal overflow and wider unfolded layouts. Header and bottom controls remain reachable inside system insets. The native camera/point-cloud occupies the measured surface rectangle beneath the transparent web component. Overlay controls remain interactive; gestures on unobstructed scene areas pass to the native renderer. Avoid unrelated cards, hero sections and decorative photos.

## 6. Motion and guidance

Animate only short opacity/transform feedback, honour reduced motion and avoid perpetual animations competing with capture. Native GL renders a single aiming target plus conservative shaded footprints. Targets adapt to reversal/new areas; all usable off-route observations still count. A bounded five-target/90-second advisory pass offers a next decision but never stops recording automatically. Green does not mean room complete. Pause keeps tracking only while the camera screen stays visible. Invalid registration hides old shading immediately.

## 7. Truth and accessibility gates

No demo records, timers that simulate capture, invented rates, fake percentages, sample room names, LiDAR claims, fake successes or hidden nominal-state templates. Static examples in input placeholders are also omitted to avoid confusing them with actual data. Genuine loading, unknown, unavailable and error states are first-class. Colour also uses outlines/patterns; icon controls have accessible names and explanations. Local UI has no external scripts/fonts/network dependency. Camera frames and geometry never travel through JavaScript messages.
